# Operational Rules

- **OR-001:** Never send real SMS during development or testing unless a future mission explicitly authorizes it.
- **OR-002:** Never hardcode secrets or provider credentials.
- **OR-003:** Do not introduce dependencies without documenting their purpose.
- **OR-004:** Do not change approved architecture silently; record and explain proposed decisions.
- **OR-005:** If a requirement conflicts with an existing architectural decision, stop and report the conflict.
- **OR-006:** Keep relevant documentation synchronized with implementation changes.
- **OR-007:** Inspect existing code and documentation before modifying them.
- **OR-008:** Run appropriate tests after implementation changes and report the commands and results.
- **OR-009:** Do not implement roadmap functionality without explicit mission authorization.
- **OR-010:** Do not silently delete or replace existing functionality.
